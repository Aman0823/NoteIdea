## Why

第一期三件必须先做对的基础工程（见 REQUIREMENTS.md 7. 分期建议），3.9 的写入通道已在 `add-write-actor` 落地。剩下两件是 **3.3 输入辅助**（定编辑器架构）与 **3.6 ID 与 DB 映射**（定数据层）。这个 change 一次做完这两件。

两件合成一个 change 而不是拆开，理由是它们共同定义「一行 md 怎么被读懂、怎么被写回」：

- 输入辅助要弹什么层，取决于解析器在光标处认出了什么 token —— 没有解析器就没有输入辅助
- `~id` 是解析结果里的一个字段，分配 ID 就是往行尾元数据区追加一个 token —— 没有解析器就没法安全地写 ID
- DB 里每条待办索引都来自解析结果，且必须能靠 `~id` 或「路径+行号+内容」定位回 md

拆开做的话，解析器的接口形状会被先做的那一半单方面绑定，另一半接进来就要返工。

时机也合适：`replace_line` / `create` 的核心逻辑与测试在 `add-write-actor` 里已就绪但一直没有调用方（当时刻意没暴露成 command）。ID 回写正是第一个真实调用方，这次把它接上。

## What Changes

- 新增 Rust 侧行内语法解析器：3.2 的五种标记 + 3.4 的四条解析与转义规则（行尾元数据区右向左扫描、引号内字面量、非法值降级为普通文本且不阻塞、解析器只读绝不改写文件）
- 新增序列化方向：把结构化的提醒时间 / 重复规则 / 标签 / 强度写回成规范化的行内标记文本，供输入辅助与 UI 回写共用
- 新增解析 command：前端每次需要判断「光标处该不该弹层、弹哪个」时 invoke Rust。**解析器只有 Rust 一份实现**，前端不复制语法规则
- 速记条接入输入辅助：敲 `@` / `!` / `#` / `^` 弹对应选择层，选中后由应用插入规范格式；Esc 收起弹层并把该字符降级为普通文本
- 新增 `~id` 身份层：待办首次需要被外部稳定引用时（设提醒 / 贴屏）才分配 ID，经 actor 的 `replace_line` 写回该行；全库查重，粘贴导致重复时为后扫到的重新分配
- 新增待办索引：启动时全量扫描 vault 内 md，把待办正文、提醒时间、重复规则、标签、强度、所属文件与行号写入 `todos` 表
- 暴露 `replace_line` / `create` 为 command（`add-write-actor` 里逻辑已就绪，此前无调用方）
- `vault/config` 增加「默认提醒时间」配置项（3.2 的时间省略规则要用，默认 09:00）

## Non-goals

明确不在这一期做，避免范围蔓延：

- **文件监听与索引增量更新**：只做启动全量扫描。监听涉及抖动去重、以及区分「自己写的」和「外部改的」，那是 FR-6 的难点，跟冲突判定的二选一弹窗一起做
- **CM6 编辑器与 chip 渲染（FR-3 / 3.5）**：输入辅助这一期只落在速记条上验证交互设计，编辑器复用同一套 command
- **提醒引擎（FR-14 / 3.8 的运行期语义）**：解析器认识 `!daily` 这些取值，但不调度、不触发、不实现「重复待办 md 恒为 `- [ ]`」的周期回写
- **聚合视图与便签（FR-7/8/9）**：它们是 `~id` 的消费方，等身份层稳了再做

## Capabilities

### New Capabilities

- `todo/syntax`: 行内标记的解析与序列化。规定扫描边界、转义规则、非法值的降级行为、以及结构化数据回写成文本的规范形式
- `todo/input-assist`: 输入辅助交互协议。规定哪些字符触发弹层、弹层选中后由谁插入格式、Esc 如何降级、解析链路慢或失败时输入不得受影响
- `todo/identity`: 待办身份。规定 `~id` 的分配时机、生成与查重、重复 ID 的处理、以及无 ID 待办如何被安全定位
- `todo/index`: 待办索引。规定索引来源、字段、重建策略，以及 md 与 DB 不一致时以谁为准

### Modified Capabilities

- `vault/config`: 增加默认提醒时间配置项（3.2 的 `@2026-08-14` 补全规则依赖它）

## Impact

**代码**
- 新增 `src-tauri/src/todo/mod.rs`、`syntax.rs`（解析与序列化）、`identity.rs`（ID 分配与查重）、`index.rs`（扫描建索引）
- `src-tauri/src/lib.rs`：注册解析、ID 分配、索引查询、`replace_line` / `create` 相关 command；`setup()` 里在 actor 就绪后触发全量扫描
- `src-tauri/src/db.rs`：`todos` 表已建，可能需补索引与 upsert 语句
- `src/quick.ts` + `quick.html` + `styles.css`：速记条加弹层
- 新增 `src/assist.ts`：弹层组件与 invoke 封装，设计上供后续 CM6 编辑器复用

**依赖**
- 时间解析可能需要 `chrono`（`@today 20:00`、`@tomorrow`、`@18:00 已过则指明天` 这类相对时间求值）。是否引入在 design 里定

**数据**
- `todos` 表开始有真实数据。全部可由重扫 md 重建，符合 D9
- vault 内 md 会因分配 `~id` 产生首次由应用主动发起的行内改写。必须只改目标行（FR-12）

**不受影响**
- NFR-2 的唤醒延迟：弹层是 show 之后的交互，不在热键关键路径上。但速记条从「纯 input」变成「input + 弹层」，需回归确认首帧可输入时间没变差
- 已归档的 `vault/file-write` 语义不变，这次只是新增调用方
