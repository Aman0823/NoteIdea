## Purpose

规定 3.2 待办行内标记的解析与序列化：从一行 markdown 文本中识别出提醒时间、重复规则、标签、提醒强度、内部 ID，以及反向把结构化数据写回成规范化的标记文本。解析器是唯一的语法真源，供输入辅助、索引扫描、编辑器渲染三方共用。

## ADDED Requirements

### Requirement: 解析器为唯一语法实现

行内标记的解析与序列化必须只有一份实现，位于 Rust 侧。前端不得复制任何语法规则，需要解析结果时通过 command 取得。

#### Scenario: 前端需要判断光标处的 token
- **WHEN** 速记条或编辑器需要知道当前行的结构或光标落在哪个标记内
- **THEN** 调用解析 command 取得结构化结果，不在前端做语法判断

#### Scenario: 索引扫描需要解析
- **WHEN** 后台扫描 vault 内 md 建立待办索引
- **THEN** 调用同一个解析函数，与前端得到的结果完全一致

### Requirement: 只在行尾元数据区识别标记

解析必须从行尾向左扫描，逐个消费符合标记模式的 token，遇到第一个不符合的 token 立即停止。停止位置左侧的一切都是正文，不得参与标记解析。

#### Scenario: 正文中含标记字符
- **WHEN** 解析 `- [ ] 给 zhang@corp.com 发邮件`
- **THEN** 扫描在 `发邮件` 处终止，`zhang@corp.com` 属于正文，不产生任何提醒时间

#### Scenario: 正文与元数据混排
- **WHEN** 解析 `- [ ] 交周报 @2026-08-14 18:00 !weekly #工作 ^ring`
- **THEN** 识别出四个标记，正文为 `交周报`

#### Scenario: 元数据区后又有正文
- **WHEN** 解析 `- [ ] 交周报 @2026-08-14 记得带U盘`
- **THEN** 扫描在 `记得带U盘` 处终止，`@2026-08-14` 属于正文，不被识别为提醒时间

### Requirement: 引号包裹是唯一的转义方式

引号内的标记字符一律是字面量，不参与解析。扫描元数据区之前必须先做引号配对并屏蔽引号内区间。不得支持反斜杠转义。

#### Scenario: 用引号保留标记字符
- **WHEN** 解析 `- [ ] 转告 "@张三" 这件事`
- **THEN** 引号内的 `@张三` 不被识别为提醒时间

#### Scenario: 引号出现在元数据区
- **WHEN** 解析 `- [ ] 提交材料 #"项目 A" ^ring`
- **THEN** 标签取值为 `项目 A`，引号本身不属于标签内容

#### Scenario: 引号未闭合
- **WHEN** 解析 `- [ ] 他说"这事` （用户正在打字的中间态）
- **THEN** 未闭合的引号视为普通字符，不屏蔽任何区间，已有解析结果不因此失效

### Requirement: 非法标记值降级为普通文本

标记值不符合取值规则时必须降级为普通文本，不得报错、不得阻塞保存、不得改写文件。同时应给出该位置的轻量提示，告知用户如需原样显示请用引号包裹。

#### Scenario: 时间格式非法
- **WHEN** 解析 `- [ ] 提醒我 @2026-13-45`
- **THEN** 该 token 降级为正文的一部分，标记为「疑似意图但未识别」以供 UI 显示轻量警告，解析整体成功

#### Scenario: 重复规则取值不在集合内
- **WHEN** 解析包含 `!biweekly` 的行（集合内为 `once/daily/weekly/monthly/yearly/weekdays/everyNd/everyNw`）
- **THEN** 该 token 降级为普通文本，不产生重复规则

#### Scenario: 解析过程中出现任何异常
- **WHEN** 解析任一行时发生非预期情况
- **THEN** 解析器绝不写文件、绝不丢弃行内容；调用方拿到的最坏结果是「整行都是正文」

### Requirement: 解析结果为完整结构而非 UI 指令

解析结果必须包含正文区间、每个已识别标记的种类与取值与字节区间、每个降级 token 的位置、以及光标当前所在的 token。不得直接返回「该弹哪个层」之类的 UI 决策。

#### Scenario: 三个消费方共用同一结果
- **WHEN** 速记条弹层、编辑器 chip 渲染、索引扫描分别请求解析
- **THEN** 三方得到同一份结构化结果，各自决定如何使用

#### Scenario: 光标位于标记内
- **WHEN** 光标落在 `@2026-08-14 18:00` 这个标记的字节区间内
- **THEN** 结果标明光标所在 token 的种类与区间，由调用方决定是否据此打开编辑弹层

### Requirement: 时间求值与解析分离

解析器只产出未求值的时间表达式。相对时间的求值必须由独立函数完成，且当前时刻作为显式参数传入，不得在解析过程中读取系统时钟。

#### Scenario: 仅有时刻且今天已过
- **WHEN** 表达式为 `18:00`，传入的当前时刻为当天 18:01
- **THEN** 求值为次日 18:00

#### Scenario: 仅有时刻且今天未过
- **WHEN** 表达式为 `18:00`，传入的当前时刻为当天 17:59
- **THEN** 求值为当天 18:00

#### Scenario: 仅有日期
- **WHEN** 表达式为 `2026-08-14`，未指定时刻
- **THEN** 补全为配置中的默认提醒时间

#### Scenario: 相对日期
- **WHEN** 表达式为 `today 20:00` 或 `tomorrow`
- **THEN** 依据传入时刻求出绝对时间，`tomorrow` 的时刻部分补全为默认提醒时间

### Requirement: 序列化产出规范格式

把结构化的时间、重复规则、标签、强度写回成行内标记文本时，必须产出唯一的规范形式。默认值（`!once`、`^toast`）应省略不写。

#### Scenario: 输入辅助插入时间
- **WHEN** 用户在时间选择器中选定了某个时刻
- **THEN** 由序列化函数产出 `@2026-08-14 18:00` 形式的文本，用户不接触格式

#### Scenario: 取值为默认值
- **WHEN** 重复规则为 `once`、提醒强度为 `toast`
- **THEN** 不写入对应标记，保持 md 简洁

#### Scenario: 序列化后再解析
- **WHEN** 对任意结构化待办序列化再解析
- **THEN** 得到与原结构等价的结果（往返一致）
