## Purpose

规定待办索引的建立与职责边界：启动时全量扫描 vault 内 md，把解析出的待办写入 SQLite 供后续聚合视图与提醒引擎查询。索引是纯派生数据，随时可弃可重建（D9）。

## ADDED Requirements

### Requirement: 索引来源与字段

索引必须完全来自对 md 文件的解析，不得包含任何只存在于 DB 的用户数据。每条记录须包含待办正文、复选框状态、提醒时间表达式、重复规则、标签、提醒强度、`~id`（若有）、所属文件路径与行号。

#### Scenario: 扫描到一条待办
- **WHEN** 扫描遇到 `- [ ] 交周报 @2026-08-14 18:00 !weekly #工作 ^ring ~a3f9`
- **THEN** 按解析结果写入索引，各字段可完整还原自该行文本

#### Scenario: 扫描到非待办行
- **WHEN** 扫描遇到普通段落、标题、代码块内容
- **THEN** 不写入索引

#### Scenario: 代码块内的复选框
- **WHEN** md 的代码块内出现形似待办的行
- **THEN** 不识别为待办（代码块中的内容是示例文本，不是用户的待办）

### Requirement: 索引可随时丢弃并重建

删除索引后重扫必须能完整恢复。任何逻辑不得把索引当作真源；md 与索引不一致时一律以 md 为准。

#### Scenario: 删库后重启
- **WHEN** 用户删除 `.noteidea/local.db` 后重启应用
- **THEN** 全量重扫重建索引，用户不应感到丢失任何自己写下的内容

#### Scenario: 索引与 md 不一致
- **WHEN** 索引中某条待办的内容与磁盘当前内容不符
- **THEN** 以磁盘内容为准，更新索引；不得用索引内容改写 md

#### Scenario: 提供手动重扫入口
- **WHEN** 用户怀疑索引已过期（这一期没有文件监听，外部编辑不会自动反映）
- **THEN** 可从界面手动触发全量重扫

### Requirement: 全量扫描不阻塞启动

启动时的全量扫描必须在后台进行，不得阻塞主窗口显示或速记条唤醒。

#### Scenario: 大 vault 启动
- **WHEN** vault 内有数千篇笔记
- **THEN** 窗口正常显示，扫描在后台推进，NFR-2 不受影响

#### Scenario: 扫描期间用户速记
- **WHEN** 索引尚未扫完，用户唤出速记条写入内容
- **THEN** 写入照常完成（追加不依赖索引），新增内容在本次或下次扫描中被收录

#### Scenario: 依赖索引的界面尚未就绪
- **WHEN** 界面需要展示待办列表而扫描未完成
- **THEN** 显示扫描进行中的状态，不得显示空列表（空列表会被误读为待办丢失）

### Requirement: 单个文件的解析失败不中断扫描

任何单个文件读取或解析失败不得中断整体扫描，也不得使已扫结果失效。

#### Scenario: 某个文件无法读取
- **WHEN** 扫描中某文件因权限或占用无法读取
- **THEN** 记录该文件为跳过并继续扫描其余文件，向用户可见地列出被跳过的文件

#### Scenario: 扫描过程中进程退出
- **WHEN** 扫描未完成时应用退出
- **THEN** 下次启动重新全量扫描，不依赖上次的部分结果
