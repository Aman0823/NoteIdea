## Purpose

规定 3.3 输入辅助的交互协议：用户敲下标记字符时由应用弹出选择层，选中后由应用插入规范化格式，使用户不必记住语法。这一期落在速记条上，同一套协议供后续 CM6 编辑器复用。

## ADDED Requirements

### Requirement: 标记字符触发选择层

在待办输入上下文中敲入 `@`、`!`、`#`、`^` 时应弹出对应的选择层。选中项后由应用插入规范化文本，用户不得需要手写格式。

#### Scenario: 敲 @ 弹时间选择
- **WHEN** 用户在速记条中敲入 `@`
- **THEN** 弹出时间选择条（今天 / 明天 / 本周五 / 下周一 / 自定义日期与时刻），选定后由应用插入规范化的时间标记

#### Scenario: 敲 ! 弹重复规则
- **WHEN** 用户敲入 `!`
- **THEN** 弹出重复规则列表，取值范围限定为 3.8 冻结的集合

#### Scenario: 敲 # 弹已有标签
- **WHEN** 用户敲入 `#`
- **THEN** 弹出 vault 内已有标签供选择，并允许输入新标签

#### Scenario: 敲 ^ 弹提醒强度
- **WHEN** 用户敲入 `^`
- **THEN** 弹出三档强度供选择

#### Scenario: 标记字符出现在正文中间
- **WHEN** 用户在正文中间（元数据区之外）敲入标记字符
- **THEN** 不弹层，该字符按普通文本处理

### Requirement: Esc 收起弹层并降级为字面量

弹层打开时按 Esc 必须收起弹层，且刚敲入的标记字符保留为普通文本，不得删除用户已输入的任何字符。

#### Scenario: 用户只想输入这个字符
- **WHEN** 弹层因用户敲入 `@` 而打开，用户按 Esc
- **THEN** 弹层关闭，`@` 保留在输入框中作为普通文本，输入焦点不变

#### Scenario: 弹层关闭后继续输入
- **WHEN** 用户按 Esc 关闭弹层后继续打字
- **THEN** 不因同一个标记字符再次弹层，除非用户重新敲入该字符

#### Scenario: 速记条上的 Esc 语义区分
- **WHEN** 速记条弹层打开时按 Esc
- **THEN** 只关闭弹层，不关闭速记条窗口；弹层未打开时按 Esc 才关闭窗口

### Requirement: 输入不得等待解析结果

按键处理必须立即完成，不得等待解析链路返回。解析慢、解析失败、后端不可用时，用户仍必须能正常输入与提交。

#### Scenario: 解析请求较慢
- **WHEN** 解析 command 的响应延迟明显
- **THEN** 字符已经出现在输入框中，弹层稍后异步出现，打字节奏不受影响

#### Scenario: 解析请求失败
- **WHEN** 解析 command 返回错误或无响应
- **THEN** 不弹层、不提示错误、不阻塞输入；用户按 Enter 仍能把内容存入 inbox

#### Scenario: 快速连续输入
- **WHEN** 用户快速打字，产生多个解析请求
- **THEN** 只有最新一次请求的结果被采用，过期响应必须丢弃，弹层状态不得与当前输入错位

### Requirement: 弹层不依赖宿主输入控件类型

弹层组件必须只接收锚点位置与当前过滤词，不得直接操作宿主输入控件。宿主适配由独立的薄适配层完成。

#### Scenario: 速记条使用弹层
- **WHEN** 弹层挂在速记条的单行输入框上
- **THEN** 由速记条的适配层提供锚点坐标并接收选中结果

#### Scenario: 后续编辑器复用弹层
- **WHEN** CM6 编辑器接入同一个弹层组件
- **THEN** 只需新增编辑器侧适配层，弹层组件本身不需修改

### Requirement: 速记条唤醒延迟不得因弹层退化

引入弹层不得影响 NFR-2。弹层相关的初始化必须在窗口预热阶段完成，不得放在热键触发后的关键路径上。

#### Scenario: 热键唤醒速记条
- **WHEN** 用户按下速记热键
- **THEN** 首帧可输入时间仍满足 NFR-2 的 200ms，弹层代码的加载不参与这段路径

#### Scenario: 弹层从未被使用
- **WHEN** 用户只输入纯文本、从不敲标记字符
- **THEN** 不产生任何解析请求，行为与引入弹层之前一致
