## Purpose

规定 3.6 待办身份：`~id` 的分配时机、生成与查重、重复 ID 的处理，以及未分配 ID 的普通待办如何被安全定位。ID 是 md 行与 DB 行之间唯一能扛住改文字、移动文件、重排顺序的映射锚。

## ADDED Requirements

### Requirement: ID 仅在需要外部稳定引用时分配

只有当一条待办首次需要被外部稳定引用时（设置提醒、或贴到屏幕上）才分配 `~id`。既无提醒又未贴屏的普通待办不得写入 ID，md 保持简洁。

#### Scenario: 用户为待办设置提醒
- **WHEN** 用户给一条尚无 ID 的待办设置提醒时间
- **THEN** 分配 ID 并写回该行，DB 中以该 ID 为主键记录提醒状态

#### Scenario: 用户把待办贴到屏幕
- **WHEN** 用户对一条尚无 ID 的待办执行贴屏
- **THEN** 分配 ID 并写回该行，便签窗口状态以该 ID 关联

#### Scenario: 普通待办被勾选
- **WHEN** 用户勾选一条既无提醒也未贴屏的待办
- **THEN** 不分配 ID，不写入任何标记，仅改写复选框字符

#### Scenario: 待办已有 ID
- **WHEN** 待办行已含 `~id`
- **THEN** 直接使用现有 ID，不重新分配

### Requirement: ID 分配与写回为原子操作

ID 分配必须在同一逻辑步骤内经 actor 写回 md。写回失败时整个操作（设提醒 / 贴屏）必须失败，DB 中不得留下引用不到 md 的记录。

#### Scenario: 写回成功
- **WHEN** ID 已成功写入 md 行
- **THEN** 提交 DB 记录，操作对用户呈现为成功

#### Scenario: 写回失败
- **WHEN** ID 写回 md 失败（权限、磁盘、行定位失败等）
- **THEN** 不提交 DB 记录，向用户报告该次操作失败，md 与 DB 均保持操作前状态

#### Scenario: 禁止延后写盘
- **WHEN** 系统需要一个 ID
- **THEN** 不得先在 DB 记录 ID 而把 md 写入延后到该行下次改动时；该中间态会在崩溃或外部编辑后造成记录永久失联，进而漏发提醒

### Requirement: ID 生成与查重

ID 为随机短哈希，4 至 8 位。生成时必须在全库查重；连续冲突时逐步扩位。不得使用内容哈希或自增整数。

#### Scenario: 生成新 ID
- **WHEN** 需要一个新 ID
- **THEN** 生成 4 位随机短哈希并在索引中查重，无冲突则采用

#### Scenario: 连续冲突
- **WHEN** 同一位宽下连续生成均与已有 ID 冲突
- **THEN** 扩展位宽重试，上限 8 位

#### Scenario: 拒绝内容哈希方案
- **WHEN** 考虑用 `hash(路径 + 正文)` 作为身份
- **THEN** 不得采用：改一个字即换身份，已触发记录随之丢失导致重复提醒重放，移动文件即失联

### Requirement: 重复 ID 的处理

同一 ID 出现在多处时（通常由复制粘贴造成），必须保留先扫到的那一处，为其余各处重新分配新 ID。

#### Scenario: 扫描发现重复 ID
- **WHEN** 索引扫描在两个位置发现相同的 `~id`
- **THEN** 先扫到的保留该 ID 与其关联的 DB 记录，后扫到的分配新 ID 并写回

#### Scenario: 重新分配的写回失败
- **WHEN** 为重复项写回新 ID 时失败
- **THEN** 该项在索引中标记为身份未确定，不得让它顶替或污染先扫到那一项的 DB 记录

### Requirement: 无 ID 待办的定位校验

无 ID 待办的写入请求必须同时携带文件路径、行号与该行当前完整内容，三者一致才允许写入。

#### Scenario: 三者一致
- **WHEN** 请求携带的行号与内容都与磁盘当前状态匹配
- **THEN** 允许写入

#### Scenario: 内容已变
- **WHEN** 行号处的实际内容与请求携带的内容不一致
- **THEN** 拒绝写入，前端刷新索引后重试，不得按行号盲写

#### Scenario: 文件中存在多行完全相同的内容
- **WHEN** 按内容重定位时匹配到多行
- **THEN** 拒绝写入并作为可见失败上报，不猜测目标行

### Requirement: ID 写回只改动目标行

写入 `~id` 时必须只改动目标行，文件其余内容逐字节不变，包括行尾换行符风格与空行数量。

#### Scenario: ID 追加到行尾元数据区
- **WHEN** 向 `- [ ] 交周报 @2026-08-14 18:00 !weekly` 写入 ID
- **THEN** 结果为该行末尾追加 ` ~a3f9`，文件其余字节完全不变

#### Scenario: 用户在外部编辑器查看 diff
- **WHEN** 用户对分配过 ID 的文件执行 git diff
- **THEN** 只看到目标行的变化，不得出现格式归一、空行调整、换行符变更等额外差异
