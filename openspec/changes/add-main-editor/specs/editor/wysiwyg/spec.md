## Purpose

规定 FR-3 / 3.5 的所见即所得渲染：原始语法何时显示、何时被 chip 取代，chip 如何交互，解析结果异步到达期间怎么渲染。贯穿全篇的底线是 D16 选 CM6 的理由——**文本是真源，渲染层永不改写文本**。

## ADDED Requirements

### Requirement: 渲染层不得改写文本

渲染层只能在文本之上叠加显示，任何情况下都不得因为渲染需要而修改文档内容。

#### Scenario: 用户手写的非规范格式
- **WHEN** 文档里存在 `*斜体*`、非标准列表符号、多余空行、未对齐的表格
- **THEN** 照原样保留，不得归一化、不得重新对齐、不得调整空行数量

#### Scenario: 打开再关闭不做任何编辑
- **WHEN** 用户打开一篇笔记，不做任何编辑就切走或关闭
- **THEN** 不产生任何写入，文件逐字节不变，`git diff` 为空

#### Scenario: 渲染需要与文本冲突
- **WHEN** 某个渲染效果只能通过改写文本实现
- **THEN** 不做该效果——这是架构判据，出现这种情况说明方案错了

### Requirement: 光标所在行显示原始语法

与当前选区相交的行显示原始 markdown 与原始标记文本，其余行渲染为最终形态。选区变化即时重算。

#### Scenario: 光标进入含标记的行
- **WHEN** 光标移入 `- [ ] 交周报 @2026-08-14 18:00 !weekly ~a3f9`
- **THEN** 该行完整显示原始文本，包括 `~a3f9`，便于直接编辑

#### Scenario: 光标离开该行
- **WHEN** 光标移出该行
- **THEN** 标记渲染为 chip，`~a3f9` 完全隐藏

#### Scenario: 跨行选中
- **WHEN** 用户框选跨越多行
- **THEN** 所有被选区触及的行都显示原始语法，不得有 chip 留在选区里挡着

#### Scenario: 多光标
- **WHEN** 存在多个选区
- **THEN** 每个选区触及的行都显示原始语法

### Requirement: 标记渲染为 chip

3.5 表格规定的五种渲染必须实现：时间为可点的日期时刻 chip、重复规则为周期 chip、标签为药丸样式、强度为图标、`~id` 完全隐藏。引号本身在渲染态隐藏。

#### Scenario: 时间标记
- **WHEN** 行内含 `@2026-08-14 18:00` 且光标不在该行
- **THEN** 渲染为带日历图标的日期时刻 chip，可点击

#### Scenario: ID 标记
- **WHEN** 行内含 `~a3f9` 且光标不在该行
- **THEN** 完全不显示，且该处不占据可见宽度

#### Scenario: 引号包裹的字面量
- **WHEN** 行内含 `"@张三"`
- **THEN** 渲染为 `@张三`，引号本身隐藏，不渲染成 chip

#### Scenario: 非法标记值
- **WHEN** 行内含 `@2026-13-45` 这类解析器判为降级的值
- **THEN** 按普通文本显示并加轻量警告下划线，悬浮提示可用引号包裹以原样显示；不得渲染成 chip，也不得阻塞编辑或保存

### Requirement: 通用 markdown 渲染为最终形态

除待办标记外，普通 markdown 语法在非选区行也必须渲染为最终形态而非源码：语法符号隐藏，块级元素按语义呈现。渲染复用编辑器已有的 markdown 语法树，不得为此引入第二个解析器。

#### Scenario: 标题
- **WHEN** 某行是 `## 本周计划` 且光标不在该行
- **THEN** `##` 与其后的分隔空格隐藏，该行按二级标题字号加粗显示

#### Scenario: 强调与行内代码
- **WHEN** 行内含 `**粗体**`、`*斜体*`、`` `代码` ``
- **THEN** `**`、`*`、反引号隐藏，文字按粗体/斜体/等宽样式显示

#### Scenario: 引用
- **WHEN** 某行以 `> ` 开头
- **THEN** `>` 与分隔空格隐藏，该行以左边条样式呈现

#### Scenario: 链接
- **WHEN** 行内含 `[文档](https://example.com)`
- **THEN** 只显示 `文档` 并带链接样式，方括号、圆括号与地址隐藏

#### Scenario: 没有替代文字的链接
- **WHEN** 行内是裸 URL 或自动链接，没有可显示的链接文字
- **THEN** 地址照常显示——隐藏它等于内容凭空消失

#### Scenario: 围栏代码块
- **WHEN** 文档含 ``` 围栏代码块
- **THEN** 围栏标记不隐藏；代码块的起止必须仍然可见

#### Scenario: 光标进入渲染行
- **WHEN** 光标移入任一被渲染的行
- **THEN** 该行所有语法符号原样恢复，可直接编辑；文档内容自始至终未被改动

### Requirement: 解析结果异步到达期间的渲染

解析器只有 Rust 一份实现，只能异步取得结果。渲染必须容忍结果尚未到达。

#### Scenario: 解析结果尚未到达
- **WHEN** 某行的解析结果还没拿到
- **THEN** 该行按原始文本显示，不渲染 chip，不得显示占位符、不得阻塞渲染、不得让编辑卡住

#### Scenario: 解析结果到达
- **WHEN** 该行的解析结果返回
- **THEN** 触发重算并渲染出 chip

#### Scenario: 解析链路不可用
- **WHEN** 后端不可用导致解析请求全部失败
- **THEN** 编辑器退化为纯文本编辑器，所有编辑、输入、保存功能保持可用

#### Scenario: 打开大文件
- **WHEN** 打开一篇数百行的笔记
- **THEN** 通过批量解析取得结果，不得逐行发起请求

### Requirement: 复选框可点击

GFM 复选框在渲染态可直接点击切换，切换后立即落盘。

#### Scenario: 点击未完成的复选框
- **WHEN** 用户点击 `- [ ]` 的复选框
- **THEN** 该行变为 `- [x]`，变更进入编辑缓冲并立即提交，只改动该行

#### Scenario: 点击时该行只改复选框字符
- **WHEN** 复选框被切换
- **THEN** 该行其余字节不变，不得触发标记重排或格式归一

### Requirement: chip 可点击修改

时间、重复规则、标签、强度四种 chip 点击后可修改。修改产生的文本必须由 Rust 序列化产出。

#### Scenario: 点击时间 chip
- **WHEN** 用户点击时间 chip
- **THEN** 打开时间选择界面，选定后由序列化产出规范文本替换原标记

#### Scenario: 前端不得自行拼接格式
- **WHEN** 需要把新的标记值写进文档
- **THEN** 文本一律由 Rust 的序列化产出；前端只负责显示层的格式化（如把 `2026-08-14 18:00` 显示为 `8月14日 18:00`），显示格式化的结果不得进入文档

#### Scenario: 修改后该行其余部分不变
- **WHEN** 时间标记被替换为新值
- **THEN** 只改动元数据区中该标记，正文与其他标记逐字节不变

### Requirement: 编辑器内的输入辅助与速记条同源

在编辑器里敲 `@` `!` `#` `^` 触发的选择层，与速记条使用同一套组件与同一套触发规则、同一套插入路径。

#### Scenario: 编辑器内敲触发字符
- **WHEN** 用户在待办行内敲 `@`
- **THEN** 弹出与速记条相同的时间选择层，选中后插入序列化产出的规范文本

#### Scenario: Esc 语义
- **WHEN** 选择层打开时按 Esc
- **THEN** 收起选择层，刚敲的字符保持为普通文本；不得因此关闭窗口或丢失输入

#### Scenario: 输入不等待解析
- **WHEN** 解析请求缓慢或失败
- **THEN** 打字、回车、方向键全程可用，不得因等待解析而阻塞按键处理
